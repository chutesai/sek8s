### Fixed
- Limit concurrent evidence requests (`/server/attest`, `/server/nvtrust/evidence`) forwarded to the host attestation-service. Each request forks a `chutes-nvevidence` run over every GPU, and the burst from a validator chute-evidence fan-out (each chute calling back through the internal port for its own GPU) OOM-killed the service under its `MemoryMax`, dropping every in-flight request. Requests from both the external and internal ports share one budget (`EVIDENCE_CONCURRENCY`, default 1); a request queued longer than `EVIDENCE_QUEUE_TIMEOUT` (default 30s) gets a `503` with `Retry-After`. Other host-service routes, including `/server/health`, are not limited.
- Callers can no longer set `expose_errors=true` as a query parameter to get upstream error detail on routes not meant to show it, including every route on the unauthenticated internal port. The flag was a defaulted handler kwarg, which FastAPI surfaces as a query param; validator-only routes now opt in with an `@expose_upstream_errors` decorator instead.
