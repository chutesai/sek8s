### Added
- VM launch now hard-matches the host's RTMR0-impacting configuration before launching, so an unbaselined host fails fast with an actionable message instead of a silent attestation 403 later. Two checks:
  - **QEMU host-readiness gate** (`verify_host_qemu_supported`, run before profile resolution): the host QEMU must be the build its OS release ships (`SUPPORTED_QEMU_BY_OS = {"25.10": "10.1.0", "26.04": "10.2.1"}`). QEMU generates the guest ACPI tables measured into RTMR0, so a different QEMU attests with an unbaselined RTMR0; tying it to the OS also enforces hosts run the release's security-patched build. Proactive operator check, not a security boundary — the real gate is the control-plane RTMR0 match.
  - **Topology hard-match** in `detect_profile`: each `GpuProfile` declares `baselined_topologies`, a set of host topology fingerprints (`detection.host_topology_fingerprint`) with baselined measurements. The fingerprint covers every device we pass through — GPUs, NVSwitches, and InfiniBand VFs — as `("numa", gpu→numa layout, nvswitch→numa layout, ib→numa layout)` on the 2-node NUMA path (where device→NUMA wiring drives the guest PXB-PCIe grouping and thus RTMR0) or `("flat", gpu_count, nvswitch_count, ib_count)` otherwise. A host whose live topology isn't baselined is refused with "run discover-profile.sh and send the output." Populated for H200 / B200 / B200_XEON6 / RTX_PRO_6000 from the captured reference hosts; an empty set (e.g. B300, not yet characterized) skips the check so it can't refuse uncharacterized hosts.
- `discover-profile.sh`: capture per-NVSwitch host NUMA node (`nvswitch.numa_nodes` in JSON, plus a report row) — the field that distinguishes otherwise-identical H200 chassis whose NVSwitches attach to a different NUMA node (e.g. Dell XE9680 node 1 vs KR6288 node 0), which changes RTMR0.
- `discover-profile.sh`: capture per-IB-PF host NUMA node for the passthrough candidates (`nic.passthrough_numa_nodes` in JSON, plus a report row) — B200/B200_XEON6 pass InfiniBand VFs through, one per PF, each attaching to its NUMA node's PXB-PCIe bridge, so IB count and IB→NUMA wiring move RTMR0 the same way GPUs and NVSwitches do.
